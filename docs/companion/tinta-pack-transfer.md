# Tinta pack transfer

Tinta language packs are part of the companion transfer requirement. Course packs and UI translation packs are distinct formats; the current reader supports a course pack at `/tinta/course.pack` (`lib/Tinta/src/platform/PackFile.h`). Runtime UI translation packs do not yet have a defined reader format or loader.

The Apple importer validates the immutable staged file with `CoursePackInspector`, publishes it by SHA-256, and stores its declared locale in SQLite library metadata. Optional `IDEN` records retain the complete assigned UID history, including retired items. Compiler, Apple importer, and reader validation support this section; legacy packs may omit it.

Reader course installation validates format, integrity, course association, locale, and item identity continuity before replacement. With identity histories, updates must retain every prior UID and digest. Learning-state detection includes legacy files and the companion journal. A legacy pack with learning state can receive an identity baseline when every existing section retains its tag, count, size, order, and exact payload bytes. Only the optional IDEN section may be added; payload offsets and header metadata may change. Changed legacy learning content still requires a baseline-preserving migration sequence before an update can be accepted. Comparisons use caller-owned scratch and periodically yield without heap allocation. Identity digests express the pack author's compatibility claim; they do not authenticate authorship.

Tinta startup verifies the confirmed active course binding and pack hash before moving legacy learner files into `/tinta/courses/<course-identity>/`. A durable migration intent and completion marker permit retry after interrupted moves. The app opens that namespace and recovers pending learner-file replacements before loading its profile. An unbound legacy installation continues using `/tinta`; orphan migration records or recovery failures prevent opening instead of creating fresh progress. Replacement checks include learner files in the selected namespace. This moves existing state files; it does not convert them into distributed history events.

The Apple transfer action now preflights course jobs through `LibraryStore.admitCourseTransfer`: it requires a complete unambiguous inventory, verifies candidate bytes and stored metadata, and rejects different confirmed courses. When both packs are in the vault, it compares verified immutable objects and rejects language changes or removed/reassigned identity history. An absent installed object or missing identity history leaves validation to the reader, which also checks learner-state presence. Preflight does not replace reader-side validation or authorize a course switch.

Stars (`starred.bin`) and completed readings (`read.bin`), including pending `.tmp`
files, migrate through a separate `course-mark-migration` intent/completion pair.
This also covers cards whose primary course-state migration already completed.
Both migrations must finish before the app opens; orphan records from either block
unbound legacy fallback. Replacement policy counts these marks in both legacy and
course-scoped directories. Test interruption after a mark moves, reboot/retry, and
confirm both stars and completed readings survive on hardware.

HAL fault tests cover every mark-migration rename before and after its effect,
failed intent/completion sync, reopening with a fresh storage object, exact mark
bytes at the destination, and unchanged repeated migration. This is host-provider
evidence; physical SD power cuts and UI preservation remain acceptance work.
